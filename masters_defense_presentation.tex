\begin{frame}{Problem Statement}
  \begin{itemize}
    \item Physical access enables firmware replacement and invasive debugging.
    \item Secure boot validates the first image but does not restrict post-boot debug/programming.
    \item Debug interfaces expose memory and execution control.
  \end{itemize}
\end{frame}

\begin{frame}{Objective}
  \begin{itemize}
    \item Enforce device-local authorization before execution and debug enablement.
    \item Keep key material out of the normal load/store path.
    \item Integrate authorization into the toolchain for reproducible, auditable binaries.
  \end{itemize}
\end{frame}

\begin{frame}{Future Work}
  \begin{itemize}
    \item Formalize boot-chain policy for BootROM placement across platforms.
    \item Add key rotation, revocation, and per-firmware authorization records.
    \item Evaluate fault/glitch resilience and side-channel leakage.
    \item Quantify area/power/latency and expand regression testing.
  \end{itemize}
\end{frame}

\begin{frame}{Conclusion}
  \begin{itemize}
    \item Instruction-triggered authorization gates execution and debug access.
    \item Protected key storage and FSM enforce device-local control.
    \item Toolchain integration enables deployable, auditable security.
  \end{itemize}
\end{frame}
