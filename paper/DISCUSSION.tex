\section{Discussion}
\label{sec:discussion}

The evaluation artifacts confirm three properties: the authorization instruction is
supported end-to-end by the build pipeline, debug enablement is released only after
explicit authorization, and failure is fail-stop with both execution and debug
disabled. These results show that authorization is enforced on-device rather than as a
host-side convention.

The threat model is addressed by storing the reference key in protected non-volatile
memory and invoking authorization via an ISA-visible trigger. This improves auditability
of compiled artifacts but makes the toolchain and provisioning workflow part of the
trusted computing base, requiring controlled distribution and lifecycle policy.

Recent work (2019--2025) strengthens secure boot, TEEs, authenticated debug, and
control-flow attestation~\cite{wang2022securebootsurvey,ahmed2025riscvtee,lapeyre2022jtagauth,benyehuda2022nanovised}.
The proposed approach complements these lines by binding authorization to an ISA-level
primitive that gates execution and debug on-device. Table~\ref{tab:discussion-positioning}
summarizes the positioning.
