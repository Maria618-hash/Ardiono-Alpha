\section{Future Work}
\label{sec:futurework}

Future work will formalize boot-chain policy for the existing BootROM placement of
\texttt{kc}, ensuring the trigger executes before any untrusted code across platform
variants and that keys are bound to device identity and boot measurements. This
includes aligning with BootROM secure boot and device identity composition (DICE) to
support measured boot and key binding that survives firmware
updates~\cite{bin2020bootrom,rv2018securebootreview,jaeger2020diceharder,parno2010bootstrapping}.
Key rotation and revocation policies should also be defined in the host database,
including per-firmware authorization records.

Debug authorization can be hardened using challenge--response protocols and rate
limiting consistent with authenticated JTAG models~\cite{lapeyre2022jtagauth,wang2020schnorrjtag}.
Resilience to fault/glitch and side-channel attacks should be evaluated, along with
area/power/latency overhead across target microcontrollers. Finally, regression
testing and formal modeling of the FSM should be extended to raise assurance in the
authorization semantics~\cite{klein2009sel4}.
